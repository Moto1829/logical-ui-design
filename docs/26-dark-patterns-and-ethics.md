# 第26章 ダークパターンと倫理的なUI
## 第26章 ダークパターンと倫理的なUI

ここまでの章では、ユーザーが迷わず、安心して目的を達成できるUIを扱ってきました。この章では逆に、認知の特性を利用して、ユーザーが本来望まない行動を取らせるUIを扱います。こうした設計はダークパターンと呼ばれます。仕組みを知っておくことは、意図せず同じ設計をしてしまうことを防ぎ、レビューで根拠を持って指摘するために役立ちます。

## 1. ダークパターンは原則の裏返しである

ダークパターンは、特別な技術ではありません。この教材で扱ってきた原則を、ユーザーの不利益になる方向に使ったものです。

- 視覚的な強弱（第18章）を使って、事業者に有利な選択肢だけを目立たせる
- 文言（第16章）を使って、断る選択に罪悪感を持たせる
- 段階的開示（第12章）を使って、費用や条件を最後まで隠す
- 確認の手間（第13章）を、解約や退会のときだけ過剰にする

つまり、ダークパターンかどうかは使われている手法ではなく、誰の利益のためにユーザーの判断を誘導しているかで決まります。同じ強調でも、誤操作を防ぐためなら良い設計であり、意図しない契約をさせるためならダークパターンです。

## 2. 代表的なパターンを知っておく

実務でよく見られるものを、仕組みとあわせて整理します。

| パターン | 例 | 利用している特性 |
| --- | --- | --- |
| 恥をかかせる断り文句 | 「いいえ、割引は必要ありません」 | 断ることへの心理的な抵抗 |
| 事前のチェック | メール配信やオプション購入に最初からチェックが入っている | 既定値をそのまま受け入れやすい傾向 |
| 後出しの費用 | 最終確認の画面で初めて手数料が加わる | 時間をかけた手続きを途中でやめにくい心理 |
| 解約の迷路 | 登録は1画面なのに、解約は電話や何段階もの確認が必要 | 手間が大きいと行動を諦める傾向 |
| 偽りの緊急性 | 根拠のない残り時間や「残りわずか」の表示 | 損失を避けたい心理 |
| 視覚的な誘導 | 有料プランのボタンだけを強調し、無料で続ける選択肢を薄い文字のリンクにする | 目立つものから選ぶ傾向 |

これらはいずれも、短期的には登録率や売上を上げるように見えます。しかし、ユーザーが後で気づいたときには、サービス全体への不信になって返ってきます。

## 3. 既定値は事業者の意図が最も表れる場所

第2章で扱ったとおり、ユーザーは画面のすべてを読みません。そのため、何も操作しなかったときの状態、つまり既定値の影響は非常に大きくなります。

判断の目安:

- 既定値は、多くのユーザーにとって安全で不利益のない選択にする
- 追加の費用や個人情報の提供につながる選択肢を、最初から選択済みにしない
- 既定値を変更できることと、変更した場合の影響を分かるようにする

「ほとんどの人が選んでいるから」という理由だけで、有料オプションを既定値にするのは適切ではありません。それがユーザーにとって最善かどうかで判断します。

なお、日本でも欧州でも、事前のチェックによる同意や、解約を不当に難しくする設計は、規制の対象として議論が進んでいます。法令に反しないかどうかは個別の確認が必要ですが、倫理の問題は法務の問題にもなりうると考えておくべきです。

## 4. 入口と出口の対称性を確かめる

ダークパターンを見つけるための実用的な方法は、反対方向の操作と比べることです。

- 登録と解約は、同じくらいの手間でできるか
- 同意と拒否は、同じくらい見つけやすいか
- オプションを付ける操作と外す操作は、同じ画面でできるか
- 通知を受け取る設定と止める設定は、同じ場所にあるか

片方だけが極端に簡単なら、その差には理由があるはずです。その理由がユーザーの利益ではなく事業者の都合であれば、設計を見直す対象になります。

第13章で扱った危険操作の確認は、ユーザーを守るためのものです。解約の画面で何度も引き止めの確認を重ねることは、同じ確認という手法を、ユーザーを守るためではなく引き止めるために使っています。

## 5. レビューでどう指摘するか

ダークパターンは、多くの場合、事業上の目標から生まれます。そのため、レビューで「倫理的に良くない」と指摘するだけでは、議論が平行線になりがちです。

指摘の組み立て方:

- 画面上の事実を示す: 「解約ボタンが3階層目のヘルプページにしかない」
- ユーザーに起きることを示す: 「解約したい人が見つけられず、問い合わせが増える」
- 事業への影響を示す: 「不信感からの低評価、返金対応、規制対応のリスクがある」
- 代替案を示す: 「解約は設定画面に置き、引き止めの提案は1回だけにする」

第7章と第17章で扱ったレビューの書き方は、ここでもそのまま使えます。好みや正義感ではなく、根拠と影響で話すことが、設計を変えるための最短の道です。

## 6. 倫理的なUIの条件

- 選択肢の強弱が、ユーザーの利益に沿って付けられている
- 断る選択肢が、同じくらい見つけやすく、責める言葉を使っていない
- 費用や条件が、判断の前に分かる
- 既定値が、ユーザーにとって不利益のない状態になっている
- 始める操作とやめる操作の手間が釣り合っている

ダークパターンは、短期的な指標を改善する代わりに、長期的な関係を損ないます。

- 信頼を失う: 誘導に気づいたユーザーは、他の表示も疑うようになる
- 問い合わせが増える: 意図しない契約や請求への対応が発生する
- 評判が下がる: 解約のしにくさや後出しの費用は、口コミで広がりやすい
- 法的なリスクを負う: 消費者保護の規制に抵触する可能性がある

UIは、ユーザーの判断を助けることも、ゆがめることもできます。この教材で学んだ原則は、助けるために使うものです。最後に、この章の要点をまとめます。

## 7. この章の要点

- ダークパターンは、UIの原則をユーザーの不利益になる方向に使ったものである
- 判断の基準は、使っている手法ではなく、誰の利益のための誘導かである
- 既定値は、ユーザーにとって不利益のない状態にする
- 入口と出口の手間を比べると、ダークパターンを見つけやすい
- レビューでは、事実、ユーザーへの影響、事業への影響、代替案の順で指摘する

## 迷いやすい判断

**解約の前に引き止めの提案を出してよいか**

1回だけ、解約の妨げにならない形であれば、利用者にとって有益な場合もあります（割安なプランへの変更、一時停止の選択肢など）。ただし、解約を続ける操作が同じくらい見つけやすく、提案を何度も重ねないことが条件です。提案を断るたびに別の提案が出る設計は、解約の迷路です。

**事業の目標と、ユーザーの利益が衝突したとき**

短期的な指標（登録率、購入率など）だけでなく、長期的な指標（解約率、問い合わせ件数、評価など）への影響も含めて議論します。ダークパターンは短期的な指標を改善しても、長期的な指標を悪化させることが多く、その影響を数字で示すと、設計を変える判断につながりやすくなります。

> 動画配信サービスの無料体験の登録画面。「7日間無料」と大きく書かれているが、8日目から月額1,490円が自動で請求されることは、画面の最下部に小さな文字で書かれている。「お得なメールを受け取る」に最初からチェックが入っている。解約は、アプリからはできず、ウェブサイトの「ヘルプ」→「よくある質問」の中にある手順に従う必要がある。

??? note "解答例"
    - 後出しの費用: 自動で請求が始まることが目立たない。登録ボタンのすぐ近くに「8日目から月額1,490円。期間中に解約すれば請求されません」と書く
    - 事前のチェック: メール配信に最初からチェックが入っている。チェックを外した状態で始める
    - 解約の迷路: 登録はアプリでできるのに、解約はヘルプの奥にある。アプリの設定画面から、登録と同じくらいの手間で解約できるようにする
