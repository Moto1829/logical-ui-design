# 第24章 複数ステップの入力設計
## 第24章 複数ステップの入力設計

第4章では1画面のフォームを扱いました。ここでは、申し込み、契約、初期設定のように、入力を複数の画面に分ける場合を扱います。ステップに分けることは負荷を減らす有効な手段ですが、分け方を誤ると、1画面の長いフォームよりも迷いやすくなります。

## 1. ステップに分けるのは判断の単位をそろえるため

入力項目が多いとき、ステップに分ける理由は「画面が長いから」ではありません。ユーザーが一度に考える内容をそろえるためです。

分ける価値がある場面:

- 前の回答によって、後で聞く内容が変わる
- 入力の内容がまとまりごとに異なる（本人情報、支払い情報、配送先など）
- 途中で書類を探すなど、作業が中断しやすい

分けない方がよい場面:

- 項目が少なく、1画面で見渡せる
- 項目どうしを見比べながら入力する必要がある
- ステップを分けた結果、1ステップに1項目しかない

第12章で扱った段階的開示と同じく、ステップの分割は負荷を分散するための手段です。分割そのものが目的になると、画面遷移の回数だけが増えます。

## 2. 全体の長さと現在地を見せる

ステップ形式の入力では、ユーザーは「あとどれくらいで終わるのか」を常に気にしています。終わりが見えない入力は、途中での離脱を招きます。

ステップ表示で伝えるべきこと:

- 全体のステップ数
- 現在のステップ
- 各ステップで何を入力するか（「1. お客様情報」「2. お支払い」など）
- 完了したステップ

「ステップ2」のような番号だけの表示では、残りの内容が予測できません。各ステップに内容を表す短い名前を付けると、ユーザーは書類の準備などの見通しを立てられます。

分岐によってステップ数が変わる場合は、最初に最大の数を見せておき、不要になったステップを省略する方が、途中で増えるよりも不安を与えません。第21章で扱った現在地の考え方は、ステップの中でも同じように当てはまります。

## 3. 戻っても入力内容を失わない

複数ステップの入力で最も深刻な不備は、前のステップに戻ったときに入力内容が消えることです。ユーザーは確認のために戻っただけなのに、入力し直しを強いられます。

確認したい点:

- 「戻る」で前のステップに戻ったとき、入力内容が残っている
- ブラウザの戻る操作でも、同じように内容が保持される
- 前のステップの変更が後のステップに影響する場合、そのことが知らされる
- 戻る操作が、画面上で見つけやすい位置にある

第21章で扱ったとおり、戻り方をブラウザ任せにしないことが重要です。ステップの間を自由に行き来できることは、ユーザーが安心して先に進むための前提です。

## 4. 中断と再開を設計に含める

入力が長くなるほど、途中で中断される可能性は高くなります。必要な書類が手元にない、他の人に確認する必要がある、時間がなくなった、といった理由はよくあります。

対策の基本:

- 入力内容を途中で保存できる、または自動で保存されることを明示する
- 再開したときに、どこまで入力したかが分かる
- 保存される期間を示す（「入力内容は7日間保存されます」）
- 最初の画面で、必要なものと所要時間の目安を伝える

最初の画面で「本人確認書類と口座番号が必要です。所要時間は約10分です」と伝えておくと、準備のないまま始めて途中で止まる、という事態を減らせます。

## 5. 確認画面は「見直し」と「修正」のために置く

最後に入力内容を一覧で確認する画面は、取り消しの難しい申し込みや支払いでは特に重要です。ただし、置くだけでは役に立ちません。

良い確認画面の条件:

- 入力内容が、入力したときと同じまとまりで表示される
- 各まとまりから、該当するステップへ直接戻って修正できる
- 修正後は、確認画面に直接戻ってこられる
- 確定ボタンの文言が、確定後に起きることを表している（「申し込みを確定する」）

修正のために戻ると最初のステップからやり直しになる確認画面は、ユーザーに修正を諦めさせます。第18章で扱ったとおり、確定ボタンには押した結果を書きます。

## 6. 良い複数ステップ入力の条件

- ステップの分け方が、内容のまとまりと判断の単位に合っている
- 全体の長さ、現在地、各ステップの内容が見える
- 前のステップに戻っても、入力内容が失われない
- 中断しても再開でき、そのことが事前に伝わっている
- 確認画面から該当箇所へ直接戻って修正できる

複数ステップの設計が崩れると、入力の負担は分散されずに増えます。

- 途中で離脱する: 終わりが見えず、残りの量を予測できない
- 入力をやり直す: 戻ったときに内容が消え、同じ入力を繰り返す
- 修正を諦める: 誤りに気づいても、直す手間が大きすぎて放置する
- 準備不足で止まる: 必要なものを知らないまま始め、途中で進めなくなる

ステップの設計は、画面を分けることではなく、ユーザーの作業の流れを区切ることです。最後に、この章の要点をまとめます。

## 7. この章の要点

- ステップは、画面の長さではなく判断の単位で分ける
- 全体の長さと各ステップの内容を、最初から見せる
- 戻っても入力内容が失われないことを前提にする
- 中断と再開、必要なものの事前案内まで設計に含める
- 確認画面は、該当箇所へ直接戻って修正できるようにする

## 迷いやすい判断

**確認画面を置くか、省くか**

支払い、申し込み、契約のように、確定後に取り消しが難しい手続きでは確認画面を置きます。一方、後から簡単に編集できる内容（プロフィールの登録など）では、確認画面を省き、完了後に編集できることを示す方が手間を減らせます。確認画面を置く場合は、該当する箇所へ直接戻って修正できるようにします。

**ステップ数を多くして1画面を短くするか、少なくして1画面を長くするか**

1ステップの内容が、1つのまとまりの判断になっているかで決めます。1ステップに1項目しかないほど細かく分けると、画面の切り替えだけが増えます。逆に、内容の違うまとまりを1画面に詰め込むと、分けた意味がなくなります。

## レビューコメントの例

「申し込みの途中でブラウザの戻るボタンを押すと、入力内容がすべて消えます。前のステップを確認したいだけの利用者も、入力し直すことになります。入力内容を保持し、ブラウザの戻る操作でも前のステップに戻れるようにすることを提案します。」

「最初の画面で必要なものが案内されておらず、3ステップ目で初めて本人確認書類の画像が必要だと分かります。書類が手元にない利用者は、そこで中断することになります。最初の画面で必要なものと所要時間を示してはどうでしょうか。」

## 演習

次の手続きについて、ステップの分け方と、各ステップの名前を考えてください。

> 引っ越しに伴う住所変更の手続き。入力する内容は、本人確認（会員番号、生年月日）、新しい住所、引っ越しの日付、電気・ガス・水道の各サービスの切り替えの希望、連絡先の電話番号。

??? note "解答例"
    - 1. ご本人の確認: 会員番号、生年月日
    - 2. 新しい住所と日付: 新しい住所、引っ越しの日付
    - 3. サービスの切り替え: 電気、ガス、水道のそれぞれの希望（前のステップの住所によって選べるサービスが変わる）
    - 4. ご連絡先: 電話番号
    - 5. 内容の確認: 各まとまりから該当するステップに戻って修正できるようにする
    - 最初の画面で、会員番号が必要なことと、所要時間の目安を示す
