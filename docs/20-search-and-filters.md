# 第20章 検索とフィルタの設計
## 第20章 検索とフィルタの設計

一覧画面で情報が増えると、ユーザーは検索と絞り込みに頼るようになります。ここが曖昧だと、目的の情報にたどり着けないだけでなく、「今どんな条件で見ているのか」すら分からなくなります。この章では、検索とフィルタの役割分担、条件の可視化、結果の伝え方を整理します。

## 1. 検索とフィルタは役割が違う

似た機能に見えますが、担っている役割は別です。

- 検索: ユーザーが頭の中にある言葉から探す。対象が特定されている場合に強い
- フィルタ: 用意された条件で候補を狭める。対象が決まっていない探索に強い

ユーザーが「あの案件」を探しているなら検索、「今週の未完了のもの」を眺めたいならフィルタです。両者を1列に混ぜて並べると、どちらから手をつければよいかが分からなくなります。

悪い状態の例:

- 入力欄、タグ、並び替え、絞り込みが区別なく一列に詰め込まれている
- 検索語の入力欄と条件指定の選択肢が同じ見た目をしている
- 並び替えが絞り込みの一種のように見える

良い状態の例:

- 検索、絞り込み、並び替えが領域として分かれている
- それぞれの役割が見出しやラベルで示されている
- 並び替えは結果の順序を変えるものだと分かる位置にある

役割が分かれたら、次に重要になるのは「今どの条件が効いているか」です。

## 2. 現在の条件が見えることを最優先にする

絞り込みUIで最も多い不備は、条件を指定できるのに、指定済みの条件が見えないことです。

条件が見えないと、次の問題が起きます。

- 件数が少ない理由が、条件のせいかデータのせいか分からない
- 前回の条件が残っていることに気づかない
- どれを外せば結果が広がるのかが分からない

対策の基本:

- 有効な条件をチップやタグとして結果の近くに表示する
- 条件を折りたたむ場合でも、件数や要約は常に見える位置に残す
- 「営業 / 完了以外」のように、条件の組み合わせを文として示す

探索の途中でユーザーが知りたいのは、選べる条件の一覧ではなく、今の自分の立ち位置です。

## 3. 結果件数は条件の結果として示す

件数表示は、単なる数字ではなく、条件と結果を結びつける情報です。

- 弱い: 「125件」とだけ表示する
- 強い: 「営業 / 完了以外 に一致する案件: 12件」と表示する

後者は、件数が条件から導かれたものだと分かるため、条件を変えれば件数が変わるという関係が理解できます。これは第5章で扱ったフィードバックと同じ考え方で、操作と結果の対応が見えることが安心につながります。

可能であれば、条件を変える前に結果件数の見込みを示す方法もあります。適用してから結果を見る設計より、試行回数を減らせます。

## 4. 絞り込みは解除しやすさとセットで設計する

条件は、付けるより外すほうが難しくなりがちです。

- 条件を1つずつ外せるか
- すべての条件をまとめて解除できるか
- 解除した結果がすぐ反映されるか

この3つが揃っていないと、ユーザーは行き詰まったときに画面を再読み込みするか、一覧から離れます。特に、条件がセッションをまたいで保持される設計では、「前回の条件が残っている」ことが分かる表示と解除手段が不可欠です。

## 5. ゼロ件は空状態ではなく探索の続き

検索結果ゼロは、データがない状態ではなく、条件が絞られすぎた状態です。第10章で扱ったとおり、初回の空状態とは意味が違います。

ゼロ件で返すべき情報:

- どの条件で検索したのか
- どの条件を外すと結果が増えそうか
- 表記ゆれや入力ミスの可能性があるか
- 条件をすべて解除する手段

「見つかりませんでした」だけで終わる画面は、ユーザーに次の一手を渡していません。ゼロ件は失敗ではなく、探索の途中経過として設計します。

ここまでを踏まえると、検索とフィルタの良し悪しは、機能の多さではなく、探索状態の把握しやすさで決まります。

## 6. 良い検索とフィルタ設計の条件

- 検索、絞り込み、並び替えの役割が分かれている
- 有効な条件が結果の近くで常に見える
- 件数が条件の結果として理解できる
- 条件を1つずつ、またはまとめて解除できる
- ゼロ件のときに次の一手が示される

探索の状態が見えない一覧は、件数が多いほど使われなくなります。

- 探索が続かない: 条件を変えても何が変わったか分からず、試行が止まる
- 誤った結論が出る: 残った条件に気づかず、データがないと判断してしまう
- 同じ検索を繰り返す: 条件の解除方法が分からず、最初からやり直す
- 一覧が信用されなくなる: 結果と条件の関係が読めず、別の手段で確認され始める

検索とフィルタは、一覧画面の使い勝手を決める中心的な機能です。最後に、この章の要点をまとめます。

## 7. この章の要点

- 検索は特定の対象を探す手段、フィルタは候補を狭める手段として分ける
- 今どの条件が効いているかを、結果の近くで常に見せる
- 件数は条件の結果として提示し、操作との対応を理解させる
- ゼロ件では、条件の見直し方と解除手段を示す

## 迷いやすい判断

**絞り込みを即時に反映するか、「適用」ボタンで反映するか**

結果がすぐに返り、条件を1つずつ試しながら絞り込む使い方なら、即時に反映する方が速く探せます。結果の取得に時間がかかる場合や、複数の条件を組み合わせてから見たい場合は、「適用」ボタンで反映します。モバイルで画面全体を使う絞り込みでは、「適用」ボタンの方が、どこで結果に戻るかが分かりやすくなります。

**検索欄を目立たせるか、絞り込みを目立たせるか**

利用者が探したいものの名前を知っている場合（商品名、顧客名など）は、検索欄を目立たせます。名前は分からないが条件は分かる場合（価格帯、地域、状態など）は、絞り込みを目立たせます。両方の使い方がある画面では、検索欄を上部に置き、よく使う絞り込みをその近くに並べます。

## レビューコメントの例

「絞り込みを適用した後、どの条件が有効になっているかが一覧の上に表示されていません。詳細画面から戻ったときに、なぜ件数が少ないのか分からなくなります。有効な条件をチップとして一覧の上に並べ、1つずつ外せるようにすることを提案します。」

「検索結果がゼロ件のとき、検索語と条件が消えて初期状態に戻ります。どの条件が原因かを確かめられません。条件を残したまま、『期限の条件を外すと12件』のように緩め方を示してはどうでしょうか。」

## 演習

次の検索画面について、問題点を3つ挙げ、それぞれの改善案を考えてください。

> 求人検索サイト。左側に15個の絞り込みがすべて展開されて並んでいる。条件を変えるたびに画面全体が再読み込みされ、スクロール位置が先頭に戻る。結果の件数は一覧の最下部に表示されている。

??? note "解答例"
    - 15個の絞り込みがすべて並び、よく使う条件が埋もれている。勤務地、職種、給与などよく使う条件を上に開いて置き、他は閉じておく
    - 再読み込みでスクロール位置が戻り、条件を変えるたびに探し直しになる。結果の部分だけを更新し、絞り込みの位置を保つ
    - 件数が最下部にあり、条件の効果が分からない。件数を一覧の上部に置き、条件を変えたらすぐに更新する
