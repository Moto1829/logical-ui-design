# 第3章 情報設計とレイアウト
## 第3章 情報設計とレイアウト

UIが分かりにくい原因は、個々のパーツではなく、画面全体の情報設計にあることが少なくありません。ここでは、情報の優先順位と配置をどう考えるかを整理します。

## 1. まず優先順位を決める

すべてを強調すると、何も強調されていないのと同じです。画面内の情報は少なくとも次の3段階に分けて考える必要があります。

- 最初に見せるべき情報
- 読めば理解が深まる補足情報
- 必要な人だけが見る詳細情報

この整理をせずにUIを作ると、見出しも説明も警告もボタンもすべてが同じ強さになり、結果としてユーザーは自分で優先順位を判断しなければなりません。

設計時には、各要素に対して「最初の3秒で見えていなければ困るか」を問いかけると優先順位が見えやすくなります。

優先順位が決まると、次はその順番どおりに視線が流れる配置を作る必要があります。ここで重要になるのがレイアウトです。

## 2. レイアウトは視線を制御する

レイアウトは見た目を整えるためではなく、視線の順番を制御するためにあります。見出し、本文、補助情報、操作の並びが自然であれば、ユーザーは迷いにくくなります。

重要な観点:

- 左上から右下への流れを妨げていないか
- 重要情報が孤立していないか
- 余白が意味の区切りとして機能しているか

たとえば設定画面で、説明文が左側、スイッチが離れた右端、保存ボタンがさらに下部にあると、視線が何度も往復します。これは単なる見た目の散らかりではなく、操作までの理解コストの上昇です。

良いレイアウトは、読み順と操作順が自然につながります。見出しを読み、選択肢を確認し、最後に行動できるという流れが壊れていないかを確認します。

## 3. 余白は装飾ではなく構造

余白が不足すると、要素同士の関係が読み取りにくくなります。逆に適切な余白は、見出しと本文、ラベルと入力欄、本文とボタンの関係を自然に伝えます。

余白の設計では、すべてを均等にする必要はありません。むしろ、関係が強い要素は近く、関係が弱い要素は離すことで構造を伝えます。

見るべき点:

- セクション間の余白は十分か
- ラベルと入力欄の距離は近すぎず遠すぎないか
- 主要ボタンの前に、判断のための間があるか

## 4. タイポグラフィは可読性の設計

文字サイズ、行間、太さ、行長は、すべて理解速度に影響します。

悪い例:

- 重要見出しと本文の差が小さい
- 一行が長すぎて視線が戻りにくい
- 補助情報が薄すぎて読めない

良い例:

- 見出しと本文で役割の差が明確である
- 行間に十分な余裕がある
- 補助情報も読めるが主張しすぎない

数値の目安:

- 本文の文字サイズは、パソコンで14〜16px、スマートフォンで16px程度を基本にする
- 行間は、本文で文字サイズの1.5〜1.8倍程度にする
- 1行の長さは、日本語で35〜45文字程度に収めると読みやすい
- 文字サイズの段階は4〜6段階程度に絞り、見出しと本文の差をはっきりつける

これらは絶対の基準ではありませんが、根拠なく値を決めるよりも、目安から始めて画面に合わせて調整する方が、ばらつきを防げます。

さらに重要なのは、一つの画面で文字のルールが安定していることです。見出し、本文、注釈、ボタンラベルが毎回違うルールで組まれていると、読み手は意味の差ではなく見た目の差を都度解釈しなければなりません。

## 5. 色は意味を補強するために使う

色は雰囲気づくりだけでなく、状態や優先度を伝えるために使います。ただし色だけに意味を持たせると、判別できないユーザーが出ます。

そのため、色に加えて次の要素を併用します。

- ラベル
- アイコン
- 位置
- 形状の違い

また、ブランドカラーを強く使う場面は絞る方がよいです。画面内のすべてが鮮やかな色だと、重要な状態変化や主要ボタンの強調に使える余地がなくなります。

色、文字、余白が個別に整っていても、要素どうしの位置関係がそろっていなければ、画面全体の構造は伝わりません。次は、揃えと視線の動き方を見ます。

## 6. グリッドと揃えで関係を伝える

要素の端がそろっていると、ユーザーはそれらを同じ列、同じ階層のものとして読み取ります。逆に、端がわずかにずれていると、意味のないずれに注意を奪われ、画面が雑然とした印象になります。

揃えの基本:

- 画面全体に、列の区切り（グリッド）を決めておき、要素の端をその線に合わせる
- 同じ階層の要素は、左端をそろえる
- 数値は右端をそろえ、桁の位置を合わせる
- 中央揃えは、短い見出しや単独のボタンなどに限る

長い文章や複数行のリストを中央揃えにすると、各行の始まりの位置が変わるため、視線が行頭を探して毎回さまよいます。日本語の本文やフォームは、左揃えを基本にします。

余白の値も、自由に決めるのではなく、4px や 8px の倍数のような段階から選ぶと、画面全体のリズムがそろいます。この考え方は、第29章で扱うデザイントークンにつながります。

## 7. 視線の動き方のパターン

ユーザーがよく使う画面を見るときの視線には、いくつかの典型的なパターンが知られています。

- F型: 文章や一覧が中心の画面では、上部を横に読み、次に少し下を横に読み、その後は左端に沿って縦に流し読みする
- Z型: 要素の少ない画面では、左上から右上、左下、右下へと、Zの字を描くように視線が動く

F型の視線から分かるのは、ユーザーが各行の左端の数文字で、読むかどうかを判断しているということです。

設計上の示唆:

- 見出しやリストの項目は、最初の数文字で内容が分かるように書く
- 一覧では、最も判断に使う情報を左側の列に置く
- 要素の少ない画面では、Z型の終点（右下）に主要な操作を置くと自然に視線が届く

ただし、これらは傾向であり、画面の構造を強く作れば、視線はそれに従います。パターンに合わせることよりも、第1節で決めた優先順位どおりに視線が流れているかを確認することが重要です。

ここまでの話を実際の画面で確認するときは、要素ごとではなく全体の流れとして見ると判断しやすくなります。次は、レビュー時の確認順を整理します。

## 8. レイアウトレビューの実践

画面全体を見るときは、次の順番で確認すると判断しやすくなります。

1. 画面の目的が最初に分かるか
2. 主情報と補助情報が分離されているか
3. 主要操作が視線の終点にあるか
4. 危険操作が十分に離れているか

これはデザインツール上でも、実装後の画面でも同じです。視線の流れと情報の階層が崩れていれば、装飾を足しても根本解決にはなりません。

情報設計とレイアウトが悪いと、ユーザーは内容を理解する前に「どこから見ればよいか」を自分で決めなければなりません。これは画面理解の失敗を増やし、重要情報の見落としにつながります。

- 優先順位を誤る: 警告や主要CTAが埋もれ、重要度の低い情報から読んでしまう
- 視線が往復する: 説明、操作、補助情報が離れすぎており、理解と操作が分断される
- 読み飛ばしが増える: 構造が弱いため、必要な情報を見落とす
- 疲労感が強まる: 画面を使うたびに整理し直す必要があり、継続利用で負担が蓄積する

情報設計とレイアウトは、以降の各UIパターンでも共通する基礎です。最後に、この章の要点を簡潔にまとめます。

## 9. この章の要点

- 情報設計では、何を先に見せるかを明確にする
- レイアウトと余白は意味の区切りを伝えるために使う
- 文字と色は感覚ではなく可読性と意味伝達のために設計する
- 揃えとグリッドで、要素どうしの関係を伝える
- 行の最初の数文字で内容が分かるように書く

## 迷いやすい判断

**余白を増やすか、情報の密度を保つか**

一覧や業務画面のように、多くの項目を見比べることが目的の画面では、余白を増やしすぎると一度に見える量が減り、スクロールと記憶の負担が増えます。余白は均等に増やすのではなく、まとまりの間を広く、まとまりの中を狭くすることで、密度を保ったまま構造を伝えます。

**強調色をどこまで使うか**

1つの画面で強い色を使う要素は、主要な操作と、ユーザーが対応すべき状態（エラーや警告）に絞ります。装飾や見出しにまで強い色を使うと、本当に注意を引きたい要素が目立たなくなります。

## レビューコメントの例

「警告、お知らせ、キャンペーンの3つのバナーが同じ大きさと色で画面上部に並んでいます。対応が必要な警告が他と区別できず、読み飛ばされる恐れがあります。警告だけを残し、お知らせとキャンペーンは画面下部か通知一覧に移すことを提案します。」

「説明文が中央揃えで5行続いており、行の始まりの位置が毎回変わるため読みにくくなっています。本文は左揃えにすると、視線が行頭を探さずに済みます。」

## 演習

次の画面について、優先順位、揃え、余白の観点から問題点を挙げ、改善案を考えてください。

> 商品の詳細画面。商品名、価格、在庫、購入ボタン、商品説明、レビュー、関連商品がすべて同じ文字サイズで縦に並んでいる。各要素の間の余白はすべて24pxで、購入ボタンだけが中央揃え、他は左揃えになっている。

??? note "解答例"
    - 優先順位: 商品名、価格、在庫、購入ボタンが最初に見えるべき情報だが、説明やレビューと同じ強さで並んでいる。文字サイズと位置で差をつけ、購入の判断に必要な情報を上部にまとめる
    - 余白: すべての間隔が同じため、どこからどこまでが1つのまとまりか分からない。購入に関わる情報の間は狭く、説明やレビューとの間は広くする
    - 揃え: 購入ボタンだけ中央揃えで、左端の流れから外れている。他の要素と左端をそろえるか、幅いっぱいのボタンにする
